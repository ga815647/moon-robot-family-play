# 月亮機器人的研究與改寫說明

新版讓主持人負責提供可玩的內容，孩子能用一個詞、聲音或點頭式回應參與；明確拒絕、安靜、正在主講與睡前狀態仍有優先權。採用完整專案指令，不需安裝程式、RAG、付費附加服務或遊戲中搜尋網路。

這是提示詞設計及合成對話推演，尚無實際新版手機語音試玩結果。研究日期為2026年10月18日。公開資料不含任何家庭的真實聊天逐字稿、聊天識別碼或兒童個資。

## 為何會空轉

以下是從原指令與互動模式作的設計推論，並非對模型內部或語音系統的診斷。

| 原指令的缺口 | 容易形成的回應 | 新版處理 |
| --- | --- | --- |
| 避免搶話、等孩子、不要追問都很明確，輪到主持人要貢獻什麼卻不明確 | 以宣告陪伴取代遊戲內容 | 一般遊戲由主持人負責開場、素材及一小步進展 |
| 「嗯不代表換遊戲」沒有正面的接法 | 不敢接下去，只回嗯或等待 | 延續原場景，不把嗯解讀成選擇或新任務同意 |
| 安靜模式缺少明確的範圍與解除條件 | 一次要求安靜後，後面一直報到；或任意恢復 | 真正停下；只有明確交棒恢復。「接一句」不等於接管 |
| 把短句限制理解為不能有事件 | 只描述自己怎麼回應 | 同樣1～3個短句，可包含動作、誤會、結果或角色反應 |
| 每次把「月亮」理解為天體主題 | 重啟相似的月亮故事 | 幾乎一律預設為主持人或語音介面；僅明確天體或故事角色上下文才切換 |
| 沒有近期笑點記憶與小目標 | 改名字重演同梗，或不斷加新危機 | 保留場景與目標，追蹤最近約4次故事回應的梗，先處理上一個事件 |

重複詞語不必解讀為無意義，也不據此判定孩子的能力。它可能是呼喚、玩聲音、想重演、確認對方在場或只是當下表達。無法知道每次真正意圖，先用低負擔、可被孩子改寫的回應承接。

## 虛擬故事骰怎麼運作

先辨識停止與主講界線，再沿用現有故事。需要靈感時，從人物、地點、意外、目標、聲音、幽默與轉折中選合適的少量元素；已有故事不必七項重組。下一輪優先呈現後果、試一個方法或收束，不再開新危機。

例：小豬在車站送布丁 → 布丁晃到司機座位旁 → 小豬扶正布丁 → 平安送到候車室。孩子每次只回嗯，也能得到完整的小片段；沒有因此被分配解題任務。

「骰」是創意組合的比喻，不是外部熵、保證均勻的亂數或永久資料庫。任意字串的「鹽」不能單靠名稱保證有趣；這裡採用有語意的素材變換、近期冷卻及目標約束。新聊天或舊文已不可見時，不能保證延續記憶。

## 新舊差異

| 面向 | 原版 | 新版 |
| --- | --- | --- |
| 主持責任 | 跟隨為主，何時主動不明確 | 一般遊戲主動開場、出素材、演小結果；孩子不用一直出題 |
| 月亮 | 主要列為喜好 | 幾乎一律視為主持人或介面；不反覆問意思、不推定天文興趣、不自稱看見畫面 |
| 短回應 | 以禁止換題為主 | 保留場景推進一小步，不替孩子選擇 |
| 安靜 | 停止延伸 | 一次確認後真正停，明確交棒才恢復 |
| 聆聽 | 只在受邀時回應 | 接一句後回到孩子主講，區分單次邀請與恢復主持 |
| 素材 | 沒有組合規則 | 七類靈感，已定設定保留，每輪最多一個主要變化 |
| 防重複 | 沒有明確機制 | 近期約4次故事回應的語意冷卻；孩子喜歡重複時可陪玩 |
| 故事進展 | 由當下回覆自然形成 | 發現、嘗試、小結果；可跳過或收束，不固定輪數 |
| 學習與安全 | 原有原則 | 保留，另補角色台詞不授權工具、猜錯轉寫不當設定等界線 |
| 維護 | 手動修改專案文字 | GitHub 保存唯一正式版本；家長同步完整指令到專案 |

## 驗證方式與限制

[26組合成對話](simulated-dialogues.md)共44個新版回應位置，包含多輪短回應、停止保持、恢復主持、角色拒絕、語音轉寫不清、事實與幻想、教學、英文、睡前及安全回歸。

這些是同一作者以新舊指令作的桌上推演，不是兩個模型實際盲測、語音錄音測試或可靠度統計。部分舊版對照刻意呈現空轉風險，其他則保留原本合適的回應，避免宣稱新版在所有情境都勝出。括號標示不開口的地方是評測註記，不能當成要唸出的台詞。

| 檢查面向 | 推演中查看的證據 | 仍需成人實際觀察 |
| --- | --- | --- |
| 內容豐富度 | 呼喚與短音節後有具體動作或結果；停下時不以多說為得分 | 孩子是否覺得有趣、能理解 |
| 重複性 | 連續嗯、叫月亮、玩聲音的多輪例子不只是替換詞彙 | 長語音對話是否又回到固定口頭禪 |
| 故事連貫性 | 同一人物、地點、物品特性與小目標相連 | 對話變長後能否保留設定 |
| 尊重孩子 | 停止、拒絕、未完敘述、未定選擇都保留界線 | 語音系統是否辨識到孩子正在說話 |
| 是否過度主導 | 一次小變化，不替孩子作決定、不連續考題 | 主持份量是否符合這次孩子與家長的偏好 |

## 專案與 GitHub 的同步

正式內容在 [PROJECT_INSTRUCTIONS.md](../PROJECT_INSTRUCTIONS.md)。ChatGPT Project 使用貼入的完整內容；GitHub 連結用來標示來源。官方文件說明專案指令會套用到專案聊天，但並沒有建立任意 GitHub 連結自動同步的承諾。[OpenAI 專案文件](https://learn.chatgpt.com/docs/projects)

更新時先在 GitHub 維護完整檔案、查看差異與回歸案例，再經家長確認後把全文貼回專案。版本號可協助辨識是否同步。遊戲中不開連結，也不宣稱已讀取遠端新版；不需要部署或背景服務。

提示詞不能保證語音介面確實無聲、精準等待、不中斷、播放音效、變聲或關閉通話。成人掌握開始、停止與時間。
