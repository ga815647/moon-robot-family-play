# 正向主持指令的合成文字檢查

日期：2026-10-18。比較 v1.6.0（Git 基準 `ad5e3e3`）與本次 v1.7.0 全文。

## 結果與適用範圍

兩版十個主案例均未觀察到明確文字失敗；三組措辭小檢查各五次，全部有具體動作與後果，均未出現空轉收尾。控制組與舊版也通過，因此本批不能證明正向改寫優於舊版，不能稱為已重現再修復的行為問題。

這是成人維護工作的合成文字代理檢查，不是真實孩子聊天，不是目標 ChatGPT 語音測試，也不是成效研究。一次質性樣本只能保留可見輸出與人工判讀，不能保證後續穩定性、孩子參與、語音停頓或介面無聲。

- 主案例由同一文字代理先讀舊版、再讀新版後生成，存在歷史影響與評分者知情；不是隔離的模型 A/B。
- 主案例原以合成前文描述交付，以下保留其內容與孩子輸入；角色欄是紀錄整理，不是外部 API 逐字請求日誌。
- 措辭小檢查每次使用全新單次代理，未繼承本次對話歷史。控制組只取得下列最小角色設定；版本組只載入對應完整指令快照，不讀其他樣本輸出。
- 每組五個不同情境、每情境一次，總共十五次；不是每個情境重複五次，也沒有估計統計差異。代理仍受共通系統與安全指令約束，並非可完全控制的產品系統提示。
- 若干情境與新版內建例子相近，屬近例檢查；未見情境的泛化未驗證。所有樣本只含虛構內容，不含真實聊天、私人連結或本機路徑。
- 空字串代表當輪沒有可朗讀文字，文件中的 `""` 是紀錄記號。必要的安靜不是空轉失敗；介面實際能否無聲未測。

## 五個面向的人工判讀

| 面向 | 可見觀察 | 限制與疑慮 |
| --- | --- | --- |
| 豐富度 | 主持回合有動作、角色反應與小結果；生活與身分問題維持短答。三組微測都有可玩的內容。 | 句數不等於故事品質；沒有證據判定新版更豐富。 |
| 重複性 | 主案例 2 的三輪沿同一目標改變表演，沒有每輪換世界或連續追問。 | 五個獨立微測無法檢驗長期重複；相同情境跨組有相似解法屬正常。 |
| 連貫性 | 帽子送還、門鈴恢復、紙船靠岸、椅子穩住、布丁停滑都有因果。 | 控制紙船案末句略重複已接信結果；幾個樣本新增小鉤子或小盤子，未改寫已定設定，但不能當成輸入原有物品。 |
| 尊重 | 兩版均在「先聽他說」、明確安靜及未完句保留空白；問身分只答題，拒絕先停，真實困擾先求助。 | 只有文字邊界檢查；沒有真人對話或語音插話測試。 |
| 過度主導 | 未替孩子選紅／藍椅子，未將短回應當同意；微測由主持角色完成動作，未指派孩子救援。 | 新版主案例 6 末句直接說明座位未決，略有說明口吻；更長的共同創作與解題主導程度未測。 |

## 十個主案例：兩版實際生成輸出

案例彼此獨立；同一案例有多輪時，下一輪接續該版本的上一輪輸出。

### 1. 紙箱城堡送帽子，嗯

合成前文：

- assistant：小郵差抱著烏龜遺失的帽子，來到紙箱城堡，準備送還。

孩子依序輸入：「嗯」

**v1.6.0 實際生成：**

> 小郵差敲敲紙箱門。烏龜從小窗探出頭：「我的帽子！」小郵差往門裡送，帽沿卻卡在小門框。他把帽子側過來，一點一點送進去。「帽子先進門，我再進門。」烏龜在裡面接住帽沿，兩個人一起把帽子送過了門。

**v1.7.0 實際生成：**

> 小郵差把帽子橫著送進門，帽沿碰到紙箱，輕輕彎了一下。烏龜從門裡伸出手：「先讓帽頂進來。」小郵差抬高帽頂，慢慢把帽子轉過去。烏龜順著接住帽沿，帽子終於穿過小門。「送到了！」

人工判讀：兩版通過：原角色與送還目標持續，具體動作造成帽子進門；沒有要求孩子作答。
